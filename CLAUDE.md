# Zenn Space — Shopify Theme (Claude Code)

This is a Shopify theme repo worked on by a Claude Code agent. Drop this file in
the theme root as `CLAUDE.md`. Per-shop facts live in `specs/THEME_PROFILE.md`
(codebase) and `specs/DESIGN.md` (design system) — generated by `/profile-theme`.

## Rule 0 — Never guess
Before suggesting any Liquid filter, setting type, schema attribute, or CLI flag,
**verify it** via the `shopify-dev-mcp`, `--help`, or existing code in this theme.
The design system and codebase facts come from `specs/DESIGN.md` and
`specs/THEME_PROFILE.md` — read both before writing code.

## Workflow (NLSpec)
Use the orchestrators and commands shipped with this module:
- `/profile-theme` — (once per shop) generate `THEME_PROFILE.md` + `DESIGN.md`.
- `/start-building <feature>` — interview → ambiguity check → spec → implement →
  review → theme check → PR. `/start-bugfix <bug>` for fixes.
- Steps individually: `/interview`, `/generate-spec`, `/implement`, `/review`,
  `/check-theme`, `/visual-qa`, `/gen-image`.
- Every visual feature runs `/visual-qa` (Playwright against the dev theme) before
  a PR to the live branch.

Implement **exactly** to the approved spec — don't add what isn't specified.

## Design-system hard rules (enforced by hooks + `/review`)
- **Colors:** always CSS custom properties — never hardcode hex; never pure black.
  Use the variables and format documented in `specs/DESIGN.md`.
- **Radius:** buttons/inputs use the button-radius var; cards use the block-radius
  var (see DESIGN.md). No ad-hoc pixel radii.
- **Spacing:** use the section-rhythm and gap vars from DESIGN.md, not magic numbers.
- **Buttons:** follow DESIGN.md (case, letter-spacing, height vars, hover).
- **Shadows:** neutral-tinted per DESIGN.md, never pure black.
- Match the Liquid/CSS/JS conventions in `THEME_PROFILE.md` (whitespace control,
  `{% render %}`, section scoping, Web Component patterns). Copy from the
  reference sections listed there.

## Accessibility hard rules
- Semantic HTML (`nav`, `button`, `article`…), not bare `div`s.
- Contrast ≥ 4.5:1 (text), 3:1 (large). Visible focus styles — never
  `outline: none` without a replacement.
- Modals trap + restore focus. Inputs have `<label for>`, `aria-*`, `autocomplete`.
- ARIA live regions for dynamic updates. Honor `prefers-reduced-motion: reduce`.

## Performance hard rules
- Images via `image_tag` (auto srcset/width/height). Above-fold `loading="eager"`
  + preload the LCP image; below-fold `loading="lazy"`.
- No render-blocking JS — `defer` / `type="module"`. No long tasks (>50ms).
- No CSS `@import`. Whitespace-stripped Liquid (`{%- -%}`). `{% render %}` over
  `{% include %}`.

## Git / safety
- Feature branches only — never commit to `main`/live directly. Implement in
  worktrees; squash-merge to the feature branch; open a PR for human review.
- **Protected, never write/commit:** `config/settings_data.json` (merchant store
  config) and `.env*`. (Hooks block these.)
- Per-shop values (store domain, dev theme id, PR repo) belong in `THEME_PROFILE.md`
  / `DESIGN.md` / `visual-qa.md`, not hardcoded across the codebase.
